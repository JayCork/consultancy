# Design Tokens

A complete reference for colour, spacing, and typography. All values are CSS custom properties
defined in `packages/tokens/colors.css`. Always reference tokens by name — never use raw values directly.

```css
/* ✅ Correct */
background-color: var(--color-background);

/* ❌ Never do this */
background-color: oklch(98% 0.008 80);
```

---

## Colour

Colours are defined using [OKLCH](https://oklch.com/) for perceptual consistency across hues.
Interactive states (hover, active, subtle, container) are derived automatically using CSS relative
colour syntax — changing a base token cascades to all its variants.

Every background token has a paired `on-` token that guarantees sufficient contrast. Always use the
matching pair.

<Markdown>
{`
| Background token | Text token |
|:---|:---|

| --color-primary-container | --color-on-primary-container |

## Spacing

All spacing uses a **4px base unit**. The scale is defined as `--space-{n}` where `n` maps to
multiples of the base unit.

### The golden rule

Use **semantic aliases** wherever possible. They communicate intent and decouple your components
from raw scale values.

```css
/* ✅ Prefer semantic aliases */
padding: var(--space-component-md);
gap: var(--space-inline-md);
margin-bottom: var(--space-layout-sm);

/* 🟡 Use raw scale only for one-off layout needs */
margin-top: var(--space-8);

/* ❌ Never use raw pixel values */
padding: 16px;
```

### Semantic aliases

These are the tokens you should be reaching for in components. They map to the primitive scale
but communicate **purpose**, not just size.

#### Component padding

Use for internal padding within UI components.


<Markdown>
{`
| Token | Value | Use |
|---|---|---|
| --space-component-xs | --space-2 · 8px | Chips, badges, tight labels |
| --space-component-sm | --space-3 · 12px | Small buttons, compact inputs |
| --space-component-md | --space-4 · 16px | Default buttons and inputs |
| --space-component-lg | --space-6 · 24px | Cards, panels, form sections |
| --space-component-xl | --space-8 · 32px | Large cards, modal bodies |
`}
</Markdown>

#### Stack gaps (vertical)

Use for `gap` or `margin-bottom` when stacking elements vertically.
<Markdown>
{`
| Token | Value | Use |
|---|---|---|
| --space-stack-xs | --space-1 · 4px | Tightly packed items (e.g. label + input) |
| --space-stack-sm | --space-2 · 8px | Form field rows |
| --space-stack-md | --space-4 · 16px | List items, related content |
| --space-stack-lg | --space-6 · 24px | Section blocks within a panel |
`}
</Markdown>
#### Inline gaps (horizontal)

Use for `gap` when laying out elements in a row.
<Markdown>
{`
| Token | Value | Use |
|---|---|---|
| --space-inline-xs | --space-1 · 4px | Icon nudge to adjacent icon |
| --space-inline-sm | --space-2 · 8px | Tight inline pairs |
| --space-inline-md | --space-3 · 12px | Default icon-to-label, button row gap |
| --space-inline-lg | --space-4 · 16px | Relaxed inline groupings |
`}
</Markdown>
#### Layout gaps (page-level)

Use between distinct page sections, not within components.

| Token | Value | Use |
|---|---|---|
| `--space-layout-sm` | `--space-8` · 32px | Between related sections |
| `--space-layout-md` | `--space-12` · 48px | Between distinct sections |
| `--space-layout-lg` | `--space-16` · 64px | Page-level vertical rhythm |
| `--space-layout-xl` | `--space-24` · 96px | Hero and feature spacing |

## Typography

The type system uses **DM Sans** as the primary sans-serif and **DM Mono** for code and data.
Sizes follow a modular scale with a ratio of ~1.25.

Import the fonts in your app entry point:

```html
<link href="https://fonts.googleapis.com/css2?family=DM+Sans:ital,opsz,wght@0,9..40,300;0,9..40,400;0,9..40,500;0,9..40,600;0,9..40,700&family=DM+Mono:wght@400;500&display=swap" rel="stylesheet" />
```

### Font families

|---|---|---|
| --font-sans | 'DM Sans', sans-serif | All UI text |
| --font-serif | 'Lora', serif | Editorial, pull quotes |
| --font-mono | 'DM Mono', monospace | Code, IDs, data values |

</Markdown>
